# ADR-0003: Онлайн-заявка на кредит (после MVP)

### Дата

2026-02-27

### Автор

Иванов А.А.

## Контекст и проблема

После реализации MVP по депозитам банк планирует в течение одного года реализовать возможность подачи заявки на кредит онлайн через интернет-банк.

Кредиты являются основным источником дохода банка, поэтому для данного направления уже существует развитая автоматизация (кредитный конвейер и система скоринга).  
На данный момент онлайн-каналы не используются для кредитования.

Бизнес ожидает:

- рост конверсии за счёт онлайн-каналов;
- быстрое предварительное решение по заявке;
- минимальные изменения существующих core-систем.

## Архитектурное решение

Выбрана архитектура, при которой:

- **интернет-банк** отвечает за
  - сбор и передачу данных клиента;
  - создание заявки в АБС
  - отправка события что заявка создана в шину событий для дальнейшей обработки;
- **Оркестратор обработки кредитных заявок** является единой точкой обработки заявок на кредит и отвечает за:
  - получение задания на обработку заявки из шины событий;
  - проверку скоринга пользователя через интеграционный слой;
  - сбор данных о полльзователе от АБС;
  - автоматизированное принятие предварительного решения по заявке на основе скоринга и данных из АБС;
  - обогощение заявки данными из АБС;
  - передачу заявки в кредитный конвейер для дальнейшей обработки бэк-офисом;
- **предварительный кредитный скоринг** выполняется автоматически путём вызова существующей системы скоринга через интеграционный слой с учётом ограничений нагрузки;
- **получение данных из Бюро кредитных историй (БКИ)** осуществляется через интеграционный слой банка, без прямых вызовов из интернет-банка;
- **кредитный конвейер** используется как существующая система обработки заявок бэк-офисом и изменяется в месте получения заявок;
- **бэк-офис** продолжает участвовать в процессе принятия финального решения по заявке;

Данное решение позволяет:

- минимизировать изменения существующих core-систем;
- изолировать интернет-банк от сложности кредитного процесса;
- обеспечить масштабируемость и управляемость нагрузки;
- создать основу для дальнейшей автоматизации кредитного процесса после MVP.

## Альтернативы

### Альтернатива 1: Прямая интеграция каналов со скорингом

**Недостатки:**

- дублирование логики;
- сложность сопровождения;
- нарушение разделения ответственности.

### Альтернатива 2: Полная автоматизация без участия бэк-офиса

**Недостатки:**

- высокие риски;
- несоответствие текущей зрелости процессов;
- значительные сроки и стоимость внедрения.

## Ограничения решения

- Используется существующий кредитный конвейер
- Решение зависит от доступности внешнего БКИ
- Возможна ручная обработка части заявок
