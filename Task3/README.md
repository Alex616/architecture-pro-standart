## Решение

### Общее описание

Целью данного решения является разработка MVP для онлайн-открытия депозитов, что позволит клиентам подавать заявки на депозиты через интернет-банк, а сотрудникам банка обрабатывать эти заявки с помощью АБС.

### Компонениы интернет-банка

#### WEB UI

Интерфейс для клиентов, который позволяет подавать заявки на депозиты и просматривать их статусы.

** Стек технологий: ** React, TypeScript, HTML, CSS

#### BACKEND

Бекенд для обработки логики приложения, взаимодействия с базой данных и интеграции с АБС.

- принимает от ui заявки на открытие депозитов
- отображает статус заявки для клиента
- хранит данные о заявках в базе данных
- отправляет заявки на открытие депозитов в Шину данных для обработки сервисом обработки заявок

** Стек технологий: ** .NET Core, C#, SQL Server, REST API

#### Обработчки заявок по депозитам

Сервис слушающий очередь и обрабатывающий заявки пользователей на депозиты подданные через интернет-банк

- получает из шины данные по заявке со всеми необходимыми данными
- создает в своей бд заявку
- отправляет заявку в АБС
- ожидаем ответа от АБС по заявке
- отправка результата обработки заявки в бекенд интернет-банка

#### АБС

АБС является существующей системой банка, которая обрабатывает заявки на депозиты и управляет счетами клиентов. В рамках данного решения АБС будет интегрирована с обработчиком заявок по депозитам для получения заявок на открытие депозитов и обновления их статусов.

Основные функции АБС в рамках данного решения:

- Получение заявок на открытие депозитов от бекенда интернет-банка
- Обработка заявок сотрудниками банка
- Обновление статусов заявок в системе и отправка их обратно в обработчик заявок
- Предоставление данных для расчета ставок на депозиты, которые будут использоваться кредитным менеджером для формирования ежедневных ставок.

## Альтернативы

### Реализация синхроного подхода для обработки заявки

Альтернативным решением было бы доработать итернет-банк на прямое взаимодействие с АБС. Однако это решение увеличило бы время обработки заявки и уменьшило количество потенциальных зявок, из-за отстутствия очереди которая бы копила бы заявки, мы бы теряли клиентов которые не дождались бы обслуживания.

Вариант откланен из-за увеличения сложности и затрат на разработку, а также из-за необходимости интеграции между несколькими системами.

## Недостатки, ограничения, риски

### Ограничения

- сохраняется участие сотрудников банка в обработке заявок.
- Ставки расчитываются раз в сутки, что может не позволить оперативно реагировать на изменения рыночной обстановки.

### Риски

- Рост нагрузки на сотрудников банка при увеличении количества заявок.
